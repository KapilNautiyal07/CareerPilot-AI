# Deploying: Vercel + Render + Neon

```
browser ──► Vercel (Next.js frontend) ──/api/* rewrite──► Render (FastAPI API) ──► Neon (Postgres + pgvector)
```

The browser only talks to the Vercel domain. Vercel forwards `/api/*` to Render server-side, so
login cookies are first-party and no CORS setup is needed in the browser. Do the steps in this
order: each one needs a value from the previous step.

## 1. Neon: database (free tier)

1. Sign up at https://neon.tech and create a project. Pick a region close to Render's
   (Singapore, `aws-ap-southeast-1`, pairs with Render Singapore).
2. In **Connection details**, turn **Connection pooling off** and copy the *direct* connection
   string. It looks like
   `postgresql://user:pass@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
   - Use the direct host, not one containing `-pooler`. Migrations and the LangGraph checkpointer
     need a direct session connection.
   - The app accepts this `postgresql://` form as-is.
3. Nothing else is needed. The first API start runs the migrations, which enable `pgvector` and
   create all tables.

## 2. Render: API

1. Sign up at https://render.com with your GitHub account.
2. **New → Blueprint**, then select this repository. Render reads `render.yaml` from the repo root.
3. Fill in the values it asks for:
   - `DATABASE_URL`: the Neon direct connection string from step 1.
   - `GEMINI_API_KEY`: your key from https://aistudio.google.com/apikey.
   - `CORS_ORIGINS`: your Vercel URL. If you don't know it yet, enter `https://localhost` and change
     it after step 3.
4. Deploy. When the logs show `Startup complete`, open `https://<service>.onrender.com/api/health`.
   It should return `{"status":"ok"}`. Copy that base URL for step 3.

`JWT_SECRET` is generated by Render automatically. The app refuses to start in production with the
development secret.

## 3. Vercel: frontend

1. Sign up at https://vercel.com with GitHub and **Add New → Project**, then import this repository.
2. Set **Root Directory** to `frontend`. The framework is detected as Next.js.
3. Add the environment variable `BACKEND_URL` = `https://<service>.onrender.com` (no trailing slash).
   It's read at build time, so redeploy whenever you change it.
4. Deploy, then open the Vercel URL and create an account.
5. Back on Render, set `CORS_ORIGINS` to the final Vercel URL and let it redeploy.

## Free-tier behavior to expect

| Behavior | Why | Option |
|---|---|---|
| The first request after ~15 idle minutes takes up to a minute and may time out once | Render free instances sleep | Reload once, or switch the service to the Starter plan |
| Uploaded resume *files* are cleared on each Render deploy | The free plan has no persistent disk | Extracted resume text is stored in Neon, so analyses keep working. For durable files, use the Starter plan and uncomment `disk:` in `render.yaml` |
| A long Gemini call can make a resume upload slow | Proxy request timeout | `LLM_TIMEOUT_SECONDS=25` keeps uploads under it; if Gemini is slower, the app falls back to deterministic analysis |
| Gemini free-tier quota (429) | Per-model limits on your key | Fallback models are configured; a paid Gemini tier removes this |

## Updating

Push to the GitHub branch you deployed from. Render and Vercel both redeploy automatically.
Database migrations run on every API start.

## Security checklist

- [ ] `.env` is not committed (it's in `.gitignore`); keys live only in the Render dashboard.
- [ ] `ENVIRONMENT=production` and `COOKIE_SECURE=true` (both set by `render.yaml`).
- [ ] If an API key was ever committed or shared, revoke it and create a new one.
- [ ] Keep `numInstances: 1`. Background workflows and rate limits run inside the API process.
